# kapsel-compile proof queries

Each `.smt2` file here is one QF_BV obligation about the compiler, generated by
`tests/proofs.rs` from the current lowering:

- `KC-Rnn-<rule>.smt2`: the status logic of one lowering rule. The wasm that `compile_core`
  emits for a fixture plan is compared with the POSIX semantics of that plan; `unsat` means no
  host results make them differ.
- `layout-*.smt2`: the argument-data layout (allocator rounding, bounds, element offsets,
  record fields) over symbolic sizes up to the compiler's limits.

Only the queries are committed. Certificates (`ordeal-cert/v5` bundles, `*.cert.json`) are
produced on demand and are ignored by git.

## Where certificates come from

`cargo test -p kapsel-compile --test proofs` does, for every query:

1. regenerate it and fail if it differs from the committed file (a stale proof; the failure
   shows ordeal's verdict on the current obligation, with the counterexample when it is SAT);
2. solve it with ordeal in-process, which must answer `unsat`;
3. write the certificate to `$KAPSEL_PROOF_OUT` (a temp directory when unset);
4. read it back, re-check it with ordeal's trusted checker, and check that its certified
   echo reads back to the committed query's assertions.

`KAPSEL_BLESS=1` rewrites the queries after a deliberate change to the lowering.

CI (`.github/workflows/rust.yml`) runs this with `KAPSEL_PROOF_OUT=$RUNNER_TEMP/proofs` and
uploads the directory as the `kapsel-compile-proofs` artifact. Each release
(`.github/workflows/release.yml`) attaches `kapsel-compile-proofs.tar.gz`, its `.sha256` and
its cosign bundle `kapsel-compile-proofs.tar.gz.sigstore.json`.

## Checking a release's bundle

```sh
TAG=v0.3.0
gh release download "$TAG" -R pulseengine/kapsel -p 'kapsel-compile-proofs.tar.gz*'
sha256sum -c kapsel-compile-proofs.tar.gz.sha256
cosign verify-blob \
  --bundle kapsel-compile-proofs.tar.gz.sigstore.json \
  --certificate-identity-regexp '^https://github\.com/pulseengine/kapsel/\.github/workflows/release\.yml@' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  kapsel-compile-proofs.tar.gz
tar -xzf kapsel-compile-proofs.tar.gz
cargo install ordeal-recheck --version 0.38.1 --locked
ordeal-recheck kapsel-compile-proofs/*.cert.json
```

`ordeal-recheck` needs no solver: it decodes each bundle (verifying every content hash),
re-checks the LRAT proof against the query it carries, and re-derives the bundle's SMT-LIB
echo with the trusted printer. Exit 0 means every certificate was accepted.

To tie a certificate to the query committed at the release tag, either run the proof test at
that tag (step 4 above), or compare a bundle with its query using
`ordeal echo-check proofs/<name>.smt2 kapsel-compile-proofs/<name>.cert.json` (an ordeal build
with `--features oracle,cert-bundle`).
